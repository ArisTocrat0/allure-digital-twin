# ALLUR Production Lab — C++ / SQLite / RU · KK · EN

Локальный прототип цифрового двойника одной автомобильной линии для QOSTANAI AI INDUSTRY HACKATHON 2026. **Все производственные данные синтетические. Модель не калибрована на ALLUR и не подключена к реальному заводу.**

## Что работает

- Дискретно-событийное C++17 ядро, эталонная реализация JS, воспроизводимые seed и фиксированный порядок событий.
- Три единичных станка, ограниченные буферы, атомарный BOM, поставки, операторы/смены, поломки/ремонт, контроль, одна переделка/брак, заказы/частичные отгрузки.
- Пять понятных страниц: обзор, линия, сценарии, заказы/ресурсы, профиль. Крупные элементы, клавиатурный фокус, мобильная компоновка.
- Полные словари русского, казахского и английского интерфейса. Язык аккаунта сохраняется в БД; язык гостя — только предпочтение в localStorage. Переводы не прошли редактуру носителем казахского языка.
- Реальная SQLite БД проекта: пользователи, серверные сессии, сценарии, неизменяемые исторические результаты. Миграция применяется автоматически.
- Регистрация, вход/выход, изменение имени/языка/пароля. Scrypt с индивидуальной солью; случайные HttpOnly / SameSite=Strict сессии, в БД только хэши идентификаторов; CSRF, Origin/Host checks, лимиты запросов, проверки владельца записей.
- Пять шаблонов сценариев, редактирование циклов/seed/операторов/поставки, сохранение и сравнение с независимым исходным сценарием.

## Запуск на этом компьютере

Собранное приложение доступно только на `http://127.0.0.1:3000`. Создайте собственный локальный аккаунт: готового общего пароля нет. Email — локальный логин; письма не отправляются.

```powershell
cd C:\Users\Ergali\Documents\project\allure-digital-twin
node server.js
```

Требуется **Node.js 24+** (используется `node:sqlite`). В текущем окружении `node` есть, `npm`/`npx` нет; приложение не требует установки npm-пакетов. Если Node отсутствует в обычном PATH, `scripts/start.ps1` также умеет находить уже установленный Codex Node runtime на этом компьютере.

## Сборка из исходников

Windows: используется переносимый Zig 0.15.2 как C++ compiler, установка в систему не требуется. Скрипт проверяет закреплённый SHA256 архива с официального [ziglang.org](https://ziglang.org/download/).

```powershell
.\scripts\setup-toolchain.ps1
node scripts/build.cjs
node server.js
```

На Linux/macOS нужен доступный C++17 compiler (`c++` либо переменная `CXX`); скачивать Windows toolchain не нужно. `node scripts/build.cjs` использует `-std=c++17 -O3 -DNDEBUG`. JSON-библиотека nlohmann 3.12.0 включена в исходники с MIT-лицензией.

Если npm доступен, эквиваленты: `npm run build`, `npm start`, `npm test`, `npm run benchmark`.

UI-тест требует Playwright и установленный Microsoft Edge. Он запускает **отдельный headless-браузер**, отдельный loopback-сервер и одноразовую тестовую БД в `artifacts/`. Существующая пользовательская браузерная сессия не используется. Windows Computer Use / node_repl в текущей сессии недоступен.

- `tests/native.test.js`: полное равенство C++/JS снимков и журналов, 200 демонстрационных + 80 пошаговых граничных конфигураций.
- `tests/server.test.js`: регистрация/хэши/сессии, CSRF, запрет доступа второго пользователя, сохранение конфигурации исторического прогона, рестарт SQLite, смена пароля, logout.
- `tests/locales.test.js`: совпадение всех ключей RU/KK/EN и отсутствие кириллицы в английском словаре.
- `tests/app-ui.cjs`: регистрация/вход/выход, повторные расчёты/сброс, пять сценариев, профиль, сохранение/перезагрузка, 3 языка × 5 страниц, клавиатура, 390px, отсутствие JS-ошибок. Скриншоты — `artifacts/app-*-desktop.png` и `app-en-mobile.png`.

Актуальные сырые замеры лежат в `docs/benchmark.json`; исходный медленный порт сохранён в `docs/benchmark-initial.json`. Мост использует два постоянных worker-процесса и очередь до 8 задач; UI не ждёт синхронного JS-вычисления. Пять выборок по 500 полных 8-часовых прогонов; 500 прогревочных JS-прогонов. Строятся полные снимки и журналы. `nativeMs` — вычисления C++; `nativeWallMs` также включает запуск процесса и JSON-вывод. Это не скорость UI/БД и не обещание такого же ускорения на любой машине. Первый прямой порт был медленнее JS; лишние копирования JSON были устранены.

## Структура

```text
src/
  simulation/model.hpp       типизированная C++ модель событий/ресурсов
  simulation/main.cpp        JSON-lines CLI адаптер и таймер
  domain/reference.cjs       проверенный JS-эталон и исходная конфигурация
  server/main.cjs            HTTP API, маршруты, авторизация записей
  server/auth.cjs            scrypt, сессии, криптографические идентификаторы
  server/database.cjs        SQLite и миграция
  server/validation.cjs      границы пользовательского ввода
  server/simulation.cjs      очередь и два переиспользуемых C++ worker-процесса
  web/                      UI и словари RU/KK/EN
migrations/001_initial.sql   схема БД и версия миграции
scripts/                    сборка, toolchain, benchmark, запуск
tests/                      ядро, C++, API, локали, браузер
third_party/                nlohmann/json + MIT attribution
```

`data/allur.sqlite` создаётся при первом запуске. `data/`, `tools/`, `build/`, `artifacts/`, `.env` исключены из Git. Тесты не используют основную БД и не затрагивают соседние проекты. Для резервного копирования остановите сервер и скопируйте папку `data/`; не копируйте только sqlite-файл во время активной WAL-записи.

## Семантика и ограничения

- Время и ресурсы целые. Смена/ремонт/ожидание оператора сохраняют остаток обработки; ремонт идёт по календарному времени. Операторы универсальны, приоритет контроль → сборка → кузов, обработка допускает прерывание.
- BOM (1 кузов + 1 двигатель + 4 колеса) целиком расходуется при запуске. Выходной станок удерживает изделие, если следующий буфер полон. `starved` и `blocked` различаются.
- Порядок на общей отметке: накопить работу до границы; поставки, поломки, ремонт, смены; завершения/контроль и движение downstream-first; отгрузки; дедлайны. Порядок равных событий стабилен.
- На горизонте принимаются поставки, завершаются операции и отгрузки, но новые операции/переделки и списание BOM запрещены. Нужная переделка остаётся `pendingRework` в НЗП. Готово не равно отгружено, срок включительный.
- Изменение исходного объекта после создания модели не меняет очередь событий. Снимки независимы; результаты в SQLite сохраняют конфигурацию своего прогона даже после редактирования сценария.
- **Сценарии и шаги API пересчитываются от t=0. Runtime restore и ветвление из текущего состояния не реализованы.** История — результаты для просмотра/повторного расчёта, не сериализованный checkpoint очереди.
- **Monte Carlo и вероятность опоздания не реализованы.** Проценты входных дефектов — синтетические параметры. Серия seed в тестах проверяет инварианты, не оценивает риск. ML не заявляется.
- Только одна модель автомобиля и одна линия. Нет переналадок, квалификаций, затрат/энергии, внешней логистики и MES/ERP. Нет доступа к производственной БД ALLUR. SQLite хранит данные приложения, не реальные данные завода.
- Сервер рассчитан на локальную демонстрацию: loopback HTTP, без публичного deployment. Для сетевого production нужны HTTPS/Secure cookies, управляемые аккаунты/восстановление, аудит, резервное копирование, нагрузочные и независимые security-тесты. Текущие проверки не являются сертификацией безопасности или UX «10/10».

## Демонстрация

Seed 2026, 8 часов: исходный сценарий — 28 отгружено; A-101 закрыт 05:00 при сроке 04:00. Задержка — 26, дополнительная поломка — 27. Третий оператор — 28, но A-101 уже в срок 04:00. Ускорение поставки — A-101 в 03:00. Это результаты модели, не измеренный эффект на заводе.

Откройте «Сценарии» → выберите шаблон → «Рассчитать 8 часов» → сравните заказы в срок → посмотрите линию, ресурсы и журнал → сохраните свой сценарий и расчёт → смените язык → отредактируйте профиль и выйдите.
